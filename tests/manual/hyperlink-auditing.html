This page tests whether hyperlink auditing is supported by vimb/WebKitGTK. Hyperlink auditing is the browser-level ping attribute: when a link carrying ping="URL" is activated, the browser fires an asynchronious POST request to that URL (the "ping") in the background, independent of any JavaScript. The request carries the Ping-From and Ping-To headers, which is how a tracking/analytics service identifies the referrer link.

The ping is not disabled by scripts=no — it is a browser-level request, not a script. So this works with vimb's default settings.

To observe the ping, run a small HTTP sink on 127.0.0.1:8099 that prints the request it receives (including headers): 

nc -l 8099 < /dev/null
# or, to also keep listening:
while true; do nc -l 8099 < /dev/null; done

Then open this page in vimb: 

:open file:///path/to/vimb/tests/manual/hyperlink-auditing.html
  1. Activate the audit link below (focus it and press Enter, or use the follow-hints f / F).
  2. Check the sink output: it should show a POST containing a Ping-From header naming this page and a Ping-To header naming the ping URL.
  3. Activate the second, non-ping link. The sink should receive nothing — only links with a ping attribute are audited.

If you want to stop vimb from sending such pings, a user script (which you can load via :js) can intercept requests, for example by registering a WebKit resource-load-started / decide-policy handler that aborts requests carrying Ping-From/Ping-To headers.

The ping URL below points at the loopback sink; adjust the port if yours differs.
